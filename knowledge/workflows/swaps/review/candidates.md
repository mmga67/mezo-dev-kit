# Swap and routing candidate inventory

| Candidate                                                       | Decision                        | Reason                                                                                                                                                |
| --------------------------------------------------------------- | ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| Dedicated `workflows/swaps` module                              | Propose for qualified review    | Routing crosses pool families and consumes transaction lifecycle rules without owning pool accounting or generic execution.                           |
| Basic Router direct/multi-hop                                   | Evidence-verified, support none | Accepted Contract/source/ABI, current roots, current `getAmountsOut`, and exact historical two-hop replay are pinned.                                 |
| CL Router direct                                                | Evidence-verified, support none | Accepted Contract/source/ABI and exact historical `exactInputSingle` replay are pinned; the historical zero minimum is retained as negative evidence. |
| CL Router multi-hop                                             | Source-verified, support none   | `exactInput` and packed path/payer semantics are reproduced, but no historical multi-hop transaction is used as support proof.                        |
| Current official Quoter                                         | Retain as gap                   | Official current documentation publishes no Quoter coordinate.                                                                                        |
| Universal Router / command bytes / Permit2                      | Reject                          | No official deployed identity or ABI was established; upstream command numbers must not be inferred.                                                  |
| Atomic basic+CL route                                           | Reject                          | The deployed routers are separate destinations and no reviewed composer exists.                                                                       |
| Sequential basic+CL plan                                        | Requirements only               | Each leg is a distinct transaction and must be re-quoted, re-simulated, tracked, and reconciled after the prior leg.                                  |
| Unsafe/basic fee-on-transfer/CL sweep-refund-multicall families | Disabled                        | Their amount, custody, balance, or composition semantics require separate evidence and qualified review.                                              |
| Public reader/writer                                            | Out of scope                    | Requires a separate package task, interface/dependency decision, fresh exact-call evidence, tests, and qualified review.                              |
