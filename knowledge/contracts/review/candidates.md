Accepted ADR-0005 is now implemented as four explicit, non-fallback provenance
classes with network/version-scoped ABI artifacts and negative tests. Accepted
ADR-0004 is implemented by accepted Ethereum/Base capability-profile records.
These architecture changes removed the former two-artifact/Cosmos-shape
blockers, and registry provenance review entered the bounded incentives and bridge identities as
class-specific records that subsequently received qualified registry
acceptance. Downstream protocol, route, and writer support remains gated.
Deferred candidates still require complete class-specific ABI,
activation, runtime, and source evidence before they can enter the Contracts
owner. Do not fabricate a second artifact, upgrade an explorer label, or copy
workflow-local addresses to satisfy a class.

## Conflicts And Limitations Discovered

- The public testnet RPC returned current state but omitted several historical
  receipts and blocks. The observation set records each official-explorer
  fallback rather than generalizing archive support.
- Official deployment aliases such as `VeBTCVoter` map to Solidity source names
  such as `Voter`; both names are preserved instead of being treated as
  different contracts.
- The current official pool documentation is newer than the pinned public
  Tigris repository and includes a CL/veMEZO-era surface that repository does
  not reproduce. Those generations must not be merged implicitly.
- A matching address across different networks is not a shared deployment.
  Network-scoped records remain distinct.
